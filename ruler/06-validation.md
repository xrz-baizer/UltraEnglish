## 基本流程

1. 阅读适用规则，检查当前 diff，识别用户已有改动。
2. 确认改动范围仅在客户端，允许同步共享 `Requirement/CHANGELOG.md`。
3. 先检查类型与实际依赖 API，再做与改动对应的行为验证。
4. 在客户端目录运行：

```bash
npm run typecheck
npm run build
```

5. 对界面改动运行 Electron，检查真实窗口截图与交互；仅构建成功不能证明布局正确。
6. 检查变更记录、规则、翻译、产物与 diff，再交付。

`npm run lint` 虽已声明，但当前仓库未配置可直接运行的 ESLint 9 flat config；不能把它作为已通过的检查。不要为了界面改版添加一套未经项目确认的 lint 体系。

## 业务回归

- 概览：真实数量、数据失败的重试、空资料库与已有记录；不添加假统计。
- 词汇：搜索名称/描述、分类组合筛选、无匹配结果与清除；内置词库管理态不可选；自定义词库仍可管理。
- 详情/练习：章节长度、熟词过滤、恢复进度、正确/错误输入、前后词、默写切换、发音、熟词标记、完成与返回。
- 音频：空状态、文件导入、搜索/排序、播放、字幕与转录的必要流程；失败/取消不能清空已有资料。
- 设置：主题、语言、字号和快捷键仍能保存；不重置用户偏好。

为可逆的纯样式修改不编写复述实现的测试。涉及新数据聚合、IPC 或状态恢复时，验证真实输入和结果；使用适量自动化和必要的运行检查，不为覆盖率扩大范围。
